## 6. 复盘与经验

- **E-1**：T-02 的 P3-6 描述「从不调用 /api/auth/logout」容易误读为「端点缺失」——侦察先行发现端点与撤销机制早已完备，实际缺口只在调用侧，改动量从「新端点+撤销表」缩到「一次 fetch」。**清账前先读服务端现状，避免按报告字面重造轮子**。
- **E-2**：JWT 路径的 CSRF 强制覆盖一切写方法（含 logout），客户端集成时若漏掉 `X-CSRF-Token` 会得到永远 403 的「假撤销」——这类「带条件的安全语义」必须在测试里锁死请求头完整性，而不是只测状态码。
- **E-3**：两个产品的 auth.js / crypto-profile.js / sync.js 为同源副本（不在 shared_sync 门禁内），本次以镜像 diff 落地；副本一致性仍是已知债（T-09 处理 privacy-policy，auth 三件套单源化列为后续）。
