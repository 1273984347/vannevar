## 1. 执行摘要

**一句话结论：Chrome 内置 Prompt API（`LanguageModel`）适配层已接入双扩展 —— 共享模块 `vannevar-builtin-ai.js` 双副本入 STRICT 门禁（6 组全绿），5 个生成函数在「未配置云端」分支先行尝试端侧推理（零配置、零上传），输出经宽松 JSON 提取走与云端一致的解析路径；保守可用性策略确保绝不静默下载模型；Focus 45 条 / Muse 74 条 node 用例全绿，qa_all 6/6。**

## 2. 侦察结论（决定本批形状的三个事实）

| 事实 | 影响 |
|---|---|
| 两产品已有 `ai-router.js`（cloud→local→rule 三级路由）但**零调用方**——实际链路是 ai.js 两层（云端→规则引擎） | 不动路由层（避免大重构），在 ai.js 未配置分支内嵌端侧尝试，行为对调用方透明 |
| `local-model.js` 是休眠的 WebLLM 实验（600MB、默认关闭、仅 popup 可用、无调用方） | 保持现状；端侧层由 Chrome 管理模型（无 600MB 手动加载），两者后续再评估合并 |
| JWT…（无关）——ai.js 为独立模块（无 import），prompt 构造在各函数体内 | 提示词构造上提（云端与端侧共用同一 prompt），config 门分支注入端侧尝试 |

## 3. 设计决策（与备选方案）

| 决策 | 选择 | 备选与理由 |
|---|---|---|
| 优先级 | **云端（若配置）→ 端侧 → 规则** | 「端侧永远优先」会覆盖用户显式配置的 API——尊重显式选择的合约更不意外；未配置用户（多数）自动获得端侧 |
| 可用性 | 仅 `available`/`readily` 可用 | `downloadable`/`downloading` 不静默触发数百 MB 下载（下载属用户显式决策） |
| 输出解析 | 宽松 JSON 提取（首 `{` 至末 `}` + 围栏剥离） | 端侧模型无 `response_format` 保证；云端路径解析行为不变 |
| 流式 | 端侧整段生成后一次性 onChunk | LanguageModel 流式 API 兼容性待验证，一次回调对 UI 等价可用 |
| 失败语义 | 全部静默 → 下一层 | 与既有「AI 是可选增强」原则一致 |

## 6. 复盘与经验

- **E-1**：会话单例让「首次 create 失败」无法在共享实例上复现 —— 测试里用 `import('模块?变体名')` 加载全新实例是 ESM 下验证单例初始化失败路径的轻量手段。
- **E-2**：大函数内「上提提示词构造」式重构容易吞掉 config 门与 try 块（本批 Focus/Muse 各发生一次，靠 `node --check` + 通读当场修复）——这类编辑后必须立即语法检查，不能攒批。
- **E-3**：端侧层的保守可用性（不自动下载模型）是产品决策不是技术限制 ——「零配置」的承诺如果附带 600MB 静默下载就变成了反悔承诺；下载引导留给 Chrome 自身 UI 与用户显式行为。
