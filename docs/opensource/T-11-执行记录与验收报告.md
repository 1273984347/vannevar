## 2. 执行记录

### ST-A Bridge 截图重制（实拍）

```
产物：screenshots/bridge-{home,detail,stats,volunteer}.png（1280×800；home 1280×1400 整页）
流程：调试模式起服 → scripts/seed_demo_data.py --reset（官方数据集：3 项目/24 任务/15 留言/3 交接）→
      playwright 1280×800 捕获 → 逐张目检 → 替换 → 运行时状态清零（RESIDUE=0）
```

**关键发现（顺带解开一个旧谜）**：重制过程中「周末探访老人院」演示项目在彻底清库后自动重现 —— 根因是 `database.py:540 _seed_demo_data()` 的**首启内置播种**（meta 表幂等标记），十月数据「复活」之谜由此关闭（不是备份恢复，是产品设计）。旧截图停留在 6 月 22 日的旧版 UI（绿色圆角），当前管理台已是 `archive-paper.css` 档案纸感主题 —— 新截图是首次忠实反映现状的版本。

**目检结论**：四图均无「测试」字样、无参赛烙印、无瞬态状态残留（headless 下 SSE「重连中」指示条与「通知被拒绝」已按展示口径处理：volunteer/detail 隐藏指示条、通知权限经 `grant_permissions` 授予）。

## 4. 复盘与经验

- **E-1**：公开截图会过期 —— UI 演进后截图不重拍，展示面就与产品脱节。建议把「截图与当前 UI 一致性」纳入发布前目检清单（与 T-05 的图片资产目检合并为一条）。
- **E-2**：`_seed_demo_data()` 的存在意味着**空库首启必有演示数据** —— 对新用户是引导，对「纯净部署」场景（如二次开发者的 CI）需知晓 `meta.seeded` 标记语义。已沉淀本条，供部署文档后续引用。
- **E-3**：playwright + 官方播种脚本 + `grant_permissions` 的组合可在无人工参与下产出可发布级截图 —— 后续截图重制可完全脚本化（本批脚本在临时目录，如需常态化可入库为 `scripts/` 工具，另行小批次）。
