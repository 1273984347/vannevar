# T-03 · 新用户首航自测 · 执行前计划

- 日期：2026-11-03
- 执行者：AI Agent（ZCode）
- 触发：用户要求「跑一遍新用户首航自测，看看 GitHub 上开源的是否可用」

## 1. 目标

以「第一次接触本仓库的新用户」视角，从 GitHub 全新克隆出发，只依据仓库内文档（README / QUICKSTART / LOADING-GUIDE / deploy-guide）走通三条产品路径，验证开源交付物**开箱可用**。

## 2. 范围

### 做

| 步骤 | 内容 | 验收判据（可计数/布尔判定） |
|---|---|---|
| ST-A | 从 `https://github.com/1273984347/vannevar.git` 全新克隆到独立空目录（非 `D:\Vannevar`） | clone 成功 exit=0；记录 GitHub HEAD 与本地 HEAD 的差距 |
| ST-B | README/QUICKSTART 引用文件反向核对（文档里写的路径必须真实存在） | 引用文件存在率 100%，缺失清单为空 |
| ST-C | Focus/Muse 静态验证：manifest.json 可解析、manifest 引用的文件齐全、`node --check` 抽查、按文档命令跑 node 测试 | Focus 16+12 通过/0 失败；Muse 24+14+18 通过/0 失败 |
| ST-D | Bridge 新用户启动：新建 venv → `pip install -r requirements.txt` → 按文档设 `BRIDGE_JWT_SECRET`/`BRIDGE_ADMIN_PASS` → `python main.py` → `GET /health` + 管理后台 Basic Auth 登录 | /health 返回 200 `{"ok":true}`；后台首页带凭据 200 |
| ST-E | Bridge 全量 pytest（文档基线 447 passed / 9 skipped） | 0 failed；passed/skipped 数如实记录并与文档基线比对 |
| ST-F | 一键验收 `python scripts/qa_all.py`（README 宣称 6/6） | 6/6 PASS，exit=0 |
| ST-G | GitHub 仓库状态核对：CI 徽章对应工作流状态、dependabot 分支、GitHub HEAD 与本地差异 | 如实记录（本步骤是状态盘点，无 pass/fail） |

### 不做

- 不做真实浏览器人工加载扩展（无头环境用 `verify_loading` 的 zip 完整性+语法检查代替，与 T-01/T-02 同口径）；
- 不做真实 AI API 调用（验证降级链路即可，可用 `BRIDGE_AI_DEMO_MODE=1`）；
- 不跑 `qa_all.py --full` 压力测试与 Bridge e2e（与文档默认口径一致）；
- 不在首航 clone 内写任何文件（helper 脚本一律放 clone 之外），venv 除外（新用户本就会在目录内建 venv）。

- **假设（待验证）**：GitHub 上 origin/main = `c1ffd07`（本地 main 领先 1 个提交 `0ecd703`，gitignore 增补，尚未推送）。

## 4. 风险与回退
