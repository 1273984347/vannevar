## 4. 复盘

1. **审计工具自身违规**：T-04 计划初稿把被禁路径字面量写进了审计模式清单 —— 制定「禁词」规则时，执行工具最容易成为第一个违反者。已改为「引用规则位置、不写字面量」的模式并沉淀为经验 E-2。
2. **T-01 违规为何留存至今**：该行是对用户原话的忠实引用，当时的清理聚焦在代码与产品文档，「历史报告中的引语」逃过了 0 命中口径。AGENTS.md §5.3 本就要求「历史段、归档面同样要清」，本批补上了这一课。
3. **产物零残留的根因**：仓库从第一天就把 `dist/`、zip、db、log、venv 全部纳入 `.gitignore`（0ecd703 又补齐 AI 工具目录），且打包/测试产物统一输出到被忽略目录 —— 制度先行，比事后清理可靠。

## 5. 经验沉淀

- **E-1**：依赖拆分（runtime / dev）后，「跑测试」的所有文档入口（根 README、AGENTS.md、产品 README、deploy-guide）必须逐一自查安装前提；根 README 是新用户第一触点，优先级最高。
- **E-2**：引入禁词/禁路径规则时，检查脚本、计划文档、审计清单**自身**必须以「引用规则」而非「写出字面量」的方式提及目标，否则规则生效的瞬间工具链先行违规。
- **E-3**：纯净性验收以「0 命中」为口径（§5.3），且必须同时扫**当前树**与**全历史新增清单**（`git log --all --diff-filter=A`）—— 后者决定是否需要历史重写，本批结论为不需要。
- **E-4**：过程报告（`docs/opensource/`）按现行 AGENTS.md §3 属公开交付物；若未来要求「自有工作内容与公开仓物理隔离」，属结构性决策（私有工作区 + 公开发布仓），应另立批次而非在文档批次里顺手做。
