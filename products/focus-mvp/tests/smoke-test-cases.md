# Focus MVP Smoke Test 用例清单

> 本文档列出 Focus 扩展保存/恢复标签页核心流程的 smoke test 用例。当前以手工执行为主，未来可基于 Playwright + Chrome 扩展测试框架（`chrome-extension-testing` / `puppeteer` + MV3）自动化。

---

## 一、保存快照核心流程

### ST-001 保存当前窗口所有标签页

**前置条件**：浏览器打开 3 个标签页（https://example.com / https://example.org / https://example.net）
**步骤**：
1. 点击 Focus 扩展图标
2. 在 popup 中点击「保存快照」按钮
**预期**：
- popup 显示「已保存」toast
- 快照列表新增一条记录，标题为「3 个标签页」或自动生成
- chrome.storage.local 中可查到对应快照数据

### ST-002 保存含危险 scheme 的标签页（安全过滤）

**前置条件**：浏览器打开 2 个标签页（https://example.com / chrome://settings）
**步骤**：
1. 点击 Focus 扩展图标
2. 点击「保存快照」
**预期**：
- 快照保存成功，但 chrome://settings 被过滤（URL scheme 白名单：仅 http/https）
- 快照记录显示「1 个标签页」（仅 https://example.com）

### ST-003 保存空标签页（边界）

**前置条件**：浏览器仅打开 1 个空白标签页（about:blank）
**步骤**：
1. 点击 Focus 扩展图标
2. 点击「保存快照」
**预期**：
- about:blank 被过滤（非 http/https）
- 提示「无可保存的标签页」或保存空快照（取决于产品决策，当前为提示）

### ST-004 保存大量标签页（性能边界）

**前置条件**：浏览器打开 50 个标签页（https://example.com/?tab=1..50）
**步骤**：
1. 点击 Focus 扩展图标
2. 点击「保存快照」
**预期**：
- 快照保存成功，记录显示「50 个标签页」
- 保存耗时 < 2s（不卡顿 UI）
- chrome.storage.local 占用合理（参考压力测试：1000 条快约占 1.7MB）

## 二、恢复快照核心流程

### ST-005 恢复快照——重新打开所有标签页

**前置条件**：已保存 1 条快照（含 3 个标签页）
**步骤**：
1. 点击 Focus 扩展图标
2. 在快照列表中点击对应快照的「恢复」按钮
**预期**：
- 浏览器新开一个窗口
- 该窗口打开快照中的 3 个标签页
- URL 与快照保存时一致

### ST-006 恢复快照——含已失效 URL

**前置条件**：已保存 1 条快照（含 https://this-domain-does-not-exist-xxx.com）
**步骤**：
1. 点击「恢复」
**预期**：
- 浏览器尝试打开该 URL，显示无法访问（浏览器原生行为）
- 其他有效标签页正常打开
- Focus 不拦截失效 URL（只负责恢复，不负责校验可访问性）

### ST-007 恢复快照——Service Worker 已休眠

**前置条件**：已保存 1 条快照；扩展 Service Worker 已被 MV3 回收（等待 30s+ 无活动）
**步骤**：
1. 点击 Focus 扩展图标（唤醒 SW）
2. 立即点击「恢复」
**预期**：
- SW 重建后从 chrome.storage.local 重新加载 SQLite 数据库
- 快照列表正常显示
- 恢复功能正常（不因 SW 休眠丢失数据）

## 三、快照搜索与分组

### ST-008 搜索快照——按标题匹配

**前置条件**：快照列表有 5+ 条记录，部分标题含「工作」
**步骤**：
1. 在搜索框输入「工作」
**预期**：
- 列表过滤为标题含「工作」的快照
- 200ms 防抖后触发过滤（不卡顿）

### ST-009 搜索快照——按 URL 匹配

**前置条件**：快照列表有含 github.com 的快照
**步骤**：
1. 在搜索框输入「github」
**预期**：
- 列表过滤为 URL 含「github」的快照

### ST-010 搜索快照——按 AI contextTags 匹配

**前置条件**：快照有 AI 标签「深度专注」
**步骤**：
1. 在搜索框输入「深度专注」
**预期**：
- 列表过滤为 contextTags 含「深度专注」的快照

### ST-011 时间分组显示

**前置条件**：快照列表有今天/昨天/本周/更早的记录
**步骤**：
1. 查看列表（无搜索关键词）
**预期**：
- 快照按「今天 / 昨天 / 本周 / 更早」4 组显示
- 每组有分组标题

### ST-012 搜索后清空——恢复全部显示

**前置条件**：搜索框有关键词，列表已过滤
**步骤**：
1. 清空搜索框
**预期**：
- 列表恢复显示全部快照
- 时间分组重新显示

## 四、AI 上下文标签

### ST-013 AI 标签生成（已配置 API Key）

**前置条件**：Options 页配置了有效的 OpenAI 兼容 API Key
**步骤**：
1. 保存 1 条快照（含 3+ 工作相关标签页）
2. 等待 AI 标签生成（≤30s）
**预期**：
- 快照显示 AI 标签（品牌色 pill，如「深度专注 / 紧急 / 创造性」）
- 标签带「✨ AI」标识

### ST-014 AI 降级——未配置 API Key

**前置条件**：Options 页未配置 API Key
**步骤**：
1. 保存 1 条快照
**预期**：
- 快照显示规则引擎生成的标签（灰色 pill）
- 标签带「⚙️ 规则引擎」标识
- 不报错，不卡顿

### ST-015 AI 演示模式

**前置条件**：Options 页开启「演示模式」toggle
**步骤**：
1. 保存 1 条快照
**预期**：
- 快照显示预设 AI 标签（品牌色 pill +「✨ AI」标识）
- 不调用真实 API（demoMode 跳过）

### ST-016 AI 超时降级

**前置条件**：配置了一个会超时的 API 端点（如 http://10.255.255.1:8080/v1）
**步骤**：
1. 保存 1 条快照
2. 等待 30s
**预期**：
- 30s 后超时，降级到规则引擎标签
- 不报错，静默降级

## 五、数据持久化与恢复

### ST-017 数据持久化——关闭浏览器后重新打开

**前置条件**：已保存 3+ 条快照
**步骤**：
1. 完全关闭浏览器
2. 重新打开浏览器
3. 点击 Focus 扩展图标
**预期**：
- 快照列表完整显示之前的 3+ 条记录
- 数据从 chrome.storage.local 重建 SQLite 内存数据库

### ST-018 数据备份提示

**前置条件**：已保存 5+ 条快照
**步骤**：
1. 打开 Options 页
**预期**：
- 显示「数据备份提示」区块
- 提示用户定期导出快照数据
- 提供 4 条 FAQ（数据存储位置 / 浏览器更新影响 / 扩展冲突 / 数据丢失恢复）

### ST-019 MV3 SW onStartup 预热

**前置条件**：浏览器完全关闭
**步骤**：
1. 启动浏览器
**预期**：
- `chrome.runtime.onStartup` 触发
- 数据库预热（initDatabase 被调用）
- 首次点击扩展图标时无延迟（数据已预加载）

## 六、UI/UX 与无障碍

### ST-020 popup 极限宽度（280px）

**前置条件**：无
**步骤**：
1. 调整 popup 宽度到 280px（或用 DevTools 模拟）
**预期**：
- 布局不溢出、不截断
- 按钮可点击、文字可读

### ST-021 深色模式对比度

**前置条件**：系统切换到深色模式
**步骤**：
1. 打开 popup
2. 打开 Options 页
**预期**：
- 所有文字对比度 ≥ 4.5:1（正常文字）或 ≥ 3:1（大字/UI）
- 品牌色在深色背景下可读（经 check_contrast.py 校验）

### ST-022 键盘导航——Tab 循环

**前置条件**：popup 已打开
**步骤**：
1. 按 Tab 键循环焦点
**预期**：
- 焦点在可交互元素间循环（保存按钮 / 搜索框 / 快照项 / 恢复按钮）
- focus-visible 样式可见

### ST-023 prefers-reduced-motion

**前置条件**：系统开启「减少动态效果」
**步骤**：
1. 操作 popup（保存快照、搜索等）
**预期**：
- 所有动画被禁用或缩短
- viewFade 等过渡效果不执行

## 七、安全

### ST-024 URL scheme 白名单——阻止 javascript: URL

**前置条件**：快照中有一条 javascript:alert(1) URL（模拟篡改数据）
**步骤**：
1. 点击「恢复」
**预期**：
- javascript: URL 被过滤，不打开
- 仅恢复 http/https URL

### ST-025 CSP 防止内联脚本

**前置条件**：无
**步骤**：
1. 打开 DevTools Console
2. 尝试注入 `<script>alert(1)</script>` 到 popup DOM
**预期**：
- CSP 阻止内联脚本执行
- Console 显示 CSP 违规报告

## 自动化路径（未来）

当前 smoke test 以手工执行为主，未来可基于以下方案自动化：

| 方案 | 适用场景 | 优势 | 劣势 |
|------|----------|------|------|
| **Playwright + MV3** | E2E 测试 | 官方支持扩展测试 | 需配置 SW 生命周期模拟 |
| **chrome-extension-testing** | 单元+集成 | 专为扩展设计 | 社区库，维护风险 |
| **Puppeteer + chrome.runtime** | E2E 测试 | 成熟稳定 | MV3 SW 支持需额外配置 |

**优先自动化顺序**：
1. ST-001/005（保存/恢复核心流程）——最高价值
2. ST-007（SW 休眠后恢复）——MV3 特有风险
3. ST-013/014（AI 标签生成/降级）——降级路径关键
4. 其余用例逐步补齐
