# Vannevar 三产品 MVP 技术方案

> **文档说明**：本文档包含"已实现"和"规划中"两部分。标注 `[已实现]` 的功能已在 MVP 交付包中可用；标注 `[规划中]` 的功能属于未来路线图，当前 MVP 未实现。评估完成度请以 `[已实现]` 部分为准。

## 总体架构原则

- **本地优先**：用户上下文数据默认存储在本地，敏感信息不上云 `[已实现]`
- **模块化内核**：三个产品共享同一个 Context Engine 内核，仅在应用层和 UI 层做场景化扩展 `[规划中 — 当前三个产品各自独立实现，验证后再提取共享层]`
- **渐进式扩展**：MVP 聚焦核心闭环，后续通过插件和 API 扩展生态 `[规划中]`

## 一、Vannevar · Focus（学习工作）

### 1.1 产品定位

面向知识工作者的浏览器插件 + 桌面端工具，一键保存并恢复工作上下文。

### 1.2 MVP 核心功能

| 功能 | 说明 | 优先级 | 状态 |
|------|------|--------|------|
| Snapshot | 捕获当前浏览器标签页、活动窗口、打开的文档 | P0 | 浏览器标签页 `[已实现]`；活动窗口/打开的文档 `[规划中 — 需桌面端]` |
| Recall | 恢复到之前保存的窗口/标签布局 | P0 | `[已实现]` |
| Resume | AI 生成 session 摘要：关键决策、待办、下一步 | P1 | `[已实现]` |
| 本地存储 | 数据存储在本地 IndexedDB / SQLite | P0 | `[已实现 — 使用 sql.js + chrome.storage.local]` |

### 1.4 数据流

1. 用户点击「保存当前上下文」
2. 插件通过浏览器 API 获取当前窗口、标签页、URL、标题
3. 桌面端应用捕获当前活动应用和文件路径
4. Context Engine 打包成 Snapshot 对象，写入本地 SQLite
5. 用户点击「恢复」时，按保存的状态重新打开窗口和标签页

### 1.5 技术栈

| 层级 | 技术 | 状态 |
|------|------|------|
| 浏览器插件 | Chrome Extension Manifest V3 + TypeScript | MV3 `[已实现]`；TypeScript `[规划中 — 当前用原生 JS]` |
| 桌面端 | Tauri（Rust + WebView）或 Electron | `[规划中]` |
| 本地存储 | SQLite + IndexedDB | `[已实现 — sql.js（SQLite WASM）+ chrome.storage.local]` |
| AI 摘要 | 调用本地小模型或 OpenAI API（用户可选） | `[已实现 — 支持 OpenAI/Anthropic/DeepSeek 等多模型]` |
| 同步（可选） | 端到端加密云存储 | `[已实现 — Focus 与 Muse 均已支持 AES-GCM-256 + PBKDF2-SHA256 100,000 次迭代的端到端加密；salt（公开参数，非密钥）经 Bridge 档案端点 /api/auth/me/crypto-profile 上云以支持跨设备解密，passphrase 永不落盘、永不上云]` |

### 1.6 MVP 范围

- 支持 Chrome / Edge 浏览器插件 `[已实现]`
- 支持 Windows / macOS 桌面端 `[规划中]`
- 保存和恢复浏览器标签页（前 20 个） `[已实现]`
- 保存和恢复本地文件路径（通过 OS API） `[规划中 — 需桌面端]`
- AI 摘要功能可先用简单规则实现，后续接入模型 `[已实现]`

### 2.4 数据流

1. 创作者点击「捕捉灵感现场」
2. 应用读取当前播放的音乐信息（通过媒体会话 API 或播放器插件）
3. 收集当前打开的参考网页、图片、文字片段
4. 检测创作软件（Figma、Photoshop 等）的工作区状态
5. 将所有信息打包成 Muse Scene，存入项目库

## 五、隐私与安全

- **本地优先**：所有产品默认将数据存储在本地设备
- **端到端加密**：可选云端同步时，数据在客户端加密
- **最小权限**：浏览器插件只请求必要的标签页权限
- **数据可控**：用户可以随时导出或删除自己的上下文数据
